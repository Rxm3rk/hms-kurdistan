# Cross-module tests

Tests that span modules (BUILD-PROMPT §6.1, §18): the clinical scenario suites that run nightly as release gates (§18.5), end-to-end journeys with Playwright in `en`, `ckb` and `ar` and Maestro mobile flows (§18.2), performance workloads and the scaled, 300-bed and 1,000-bed days (§18.6), chaos and drill suites (§18.7), and conformance suites that run the same signed artefacts on the three-node cell and the central substrate (constitution rule 5). Unit, property and integration tests live with their modules. Every test carries its requirement and hazard IDs in its name or tags (§18.1), uses synthetic data only, and is never weakened, skipped or quarantined to get a green run (§3.5). WP-0.5 builds the scenario-suite framework, WP-0.7 the Playwright, axe and RTL-diff harnesses, WP-0.6 the workload generators and benchmark harness, WP-0.2 and WP-0.3 the first chaos tests, and WP-1.12 and WP-1.13 the conformance suites.

## Clinical scenario suites (`tests/scenarios`)

The framework of docs/specs/modules/state-machines-and-invariants.md §5: Gradle project `:tests:scenarios`, package `hms.tests.scenarios`, built from `backend/` like every backend project (`backend/settings.gradle.kts`).

- **Model** (`hms.tests.scenarios.api`, the package a binding uses). A `ScenarioSuite` has the id `SCN-<area>`, where the area is the name the hazard log plans (`ScenarioSuite:<area>`), its §18.5 number and title, its hazards, seeded hazards and SIs, the `mockKb` flag and what it waits on. A `Scenario` (`SCN-<area>-nnn`) is a list of `given`, `whenever` and `then` steps, each a text and a function on a `ScenarioWorld`. The world is made fresh for every scenario: a `SimulatedClock` (a `java.time.Clock` that only the scenario moves; zone `Asia/Baghdad`), a `SyntheticPatients` factory that issues `SYN-` identifiers only, and the domain ports the suite's binding bound.
- **Binding.** A suite runs only through a `SuiteBinding`, which the work package that builds the suite's domain implements and registers as a `ServiceLoader` provider. A suite with no binding is NOT-BUILT. A registered scenario the binding does not implement stays NOT-BUILT; a step can also throw `ScenarioNotBuiltException`. A scenario with no `then` step fails: it asserts nothing.
- **Catalogue** (`hms.tests.scenarios.application.catalogue.SuiteCatalogue`). The ten §18.5 suites, with hazards, SIs and seeded hazards taken from the hazard-log entries whose controls plan them, and scenario titles taken verbatim from §18.5. No suite has a binding, so all ten are NOT-BUILT (KA-064), each naming the §21 work packages and Appendix A features it waits on and the human gates it needs. The scenarios hold no clinical values: writing them needs CSO-approved content where §18.5 says so [HUMAN]. The self-test `SuiteCatalogueTest` checks the catalogue against the hazard log, §18.5, §21 and the backlog.
- **Runner and pass matrix.** `sh backend/gradlew -p backend :tests:scenarios:scenarioSuites` runs every catalogued suite and writes the pass matrix linked to hazards (§18.2) as `tests/scenarios/build/reports/scenarios/pass-matrix.json` and `pass-matrix.md`: suite × scenario × result (`PASS`, `FAIL` with its message, `NOT-BUILT` with what it waits on), hazards, seeded hazards, SIs and run time. Every line of a `mockKb` suite reads "mock-KB run, not clinical evidence" (§18.5 #1). The task writes the matrix first and then fails unless every suite is bound and passes, so it fails today with ten NOT-BUILT suites. It belongs to the nightly tier (step `scenario-suites`, §19.1), not to `fastTier`.
- **Self-tests** (`src/test`, in `fastTier`): the runner, the matrix and the exit-code rule on a toy fixture binding with PASS, FAIL and NOT-BUILT results, the mock-KB labelling, the synthetic patient factory, the simulated clock, the catalogue's sources and the shared architecture rules.

Not built yet: calendar-aware clock advancing (the tenant calendar, the Friday–Saturday weekend and Kurdistan holidays), and the §18.10 synthetic population with the Kurdistan locale pack (WP-0.6); both are recorded with KA-064.
