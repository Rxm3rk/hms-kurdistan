# Backend platform libraries

Shared kernel libraries, one Gradle project each, in packages `hms.kernel.<lib>` (BUILD-PROMPT §6.1). Every module may use them; they depend on no application module.

- `arch-rules` (WP-0.1): the reusable ArchUnit rules for the §6.8 fitness functions that can be expressed now, each tested against violating and compliant fixtures. See `../README.md`.
- `testing` (WP-0.1): shared test support. `PropertyTestBudget` gives every property-based test its sequence count (`hms.pbt.sequences`: 1,000 in the fast tier, 10⁶ nightly). WP-0.5 added the sequence-property harness, `hms.kernel.testing.statemachine`: `runSequences` and `machineSequenceProperties` run seeded random command sequences of a machine model, check properties P1 to P7 and write the counts file `build/pbt-counts/<name>.json` (docs/specs/modules/state-machines-and-invariants.md §3.3). Its own tests drive a toy door machine, not a clinical one.
- `state-machine` (WP-0.5): the engine behind every generated machine model, `hms.kernel.statemachine` (§8.4, Appendix B.3; spec §3.2). `MachineSpec` holds a machine's states, commands and guarded transitions and validates them when built; `fire` evaluates every guard predicate of every candidate, with no short-circuit, and returns `Fired`, `Refused` (with every failed predicate), `NotApplicable` or `Ambiguous`. Only `Fired` changes the state. Pure Kotlin with no dependency beyond the standard library, so the module domain packages can use it.
- Next, in WP-0.3 (`PLT-CORE-01`, `PLT-CORE-02`, `PLT-CORE-04`, `PLT-CORE-07`, `PLT-CFG-01`): UUIDv7 identifiers, the injected `Clock` with clinical and recorded time, `Money`, `Quantity` with UCUM, the bitemporal journal-as-outbox, the configuration chain with locks, signed configuration bundles, flags and kill switches, the task engine and `WorkflowPort`. The Trust Plane SDK and PHI-safe logging follow in WP-0.4, i18n support with the client work.
