# ADR-004: Event model: event-sourcing-lite with the bitemporal journal as the transactional outbox
Status: accepted
Date: 2026-10-18   Source: K §7.2 (kept), §7.5, §15.4 (S2), K-14; BP §7.2, §7.6, §15.4 (S2); R08 §3.5, §3.6, §3.7, §3.11, §4.3, §13 #5; R11 §14, §17 #2; RL #7; BUILD-PROMPT §2.2 rules 1–2, §5.3, §8.3, §8.5, §21 (WP-0.6), §4.2

## Context

**The question.** Whether clinical state is stored as current-state tables with a journal, or fully event-sourced.

**The research.** Full event sourcing gives perfect history, replay and natural "chart as of time T" queries, but brings complexity, event-schema evolution, tension with erasure duties (crypto-shredding is the usual workaround), mandatory read models and team unfamiliarity (R08 §3.5). R08 recommends event sourcing "lite": keep current-state tables and write an append-only journal row in the same transaction; that journal is also the outbox. Full event sourcing is worth considering only for order and MAR aggregates, where the lifecycle is the business logic (R08 §3.5). Bitemporality (valid time vs record time) is mandatory for clinical facts: vitals charted late, amended results, entered-in-error allergies, back-entry after downtime and the medico-legal "what did the doctor see at 09:12" (R08 §3.7).

**Reconciliation.** RL #7 made the R08 definition the pack standard and limited full event sourcing to order/MAR aggregates, by ADR. The prize of full event sourcing for medications is replay as a safety-case test oracle (R11 §17 #2; BP §7.6).

**Sources.** K keeps BP's decision (K §7.2; K-14 "Kept"). The medication event-sourcing question is spike S2, run inside the ADR-001 spike (BP §15.4; K §15.4). The decision is not marked [P].

## Decision

**Event model:** event-sourcing-lite, with the bitemporal journal as the transactional outbox. Full event sourcing for MedicationOrder/MedicationAdministration only if the spike shows BCMA p95 ≤500 ms, order-sign ≤1.5 s, tooling ≤8 engineer-weeks and no critical-path cost.

**BP's fuller wording of the condition** (BP §7.6): full event sourcing for the MedicationOrder and MedicationAdministration aggregates only if the spike shows BCMA p95 ≤500 ms and order-sign ≤1.5 s, schema-evolution and erasure tooling ≤8 engineer-weeks, and no added time on the critical path. The default is ES-lite. Because a calendar critical path cannot be measured by an agent, WP-0.6 reports what it can measure (files, modules and migrations touched; agent wall-clock time) and asks the human to convert it into engineer-weeks (BUILD-PROMPT §21, WP-0.6).

**Storage shapes** (BUILD-PROMPT §5.3; R08 §3.11):
- **A.** Relational aggregates with foreign keys and exclusion constraints (for example, no double bed occupancy).
- **B.** Immutable facts with `valid_period`, `recorded_at`, `author`, `attester`, `source` (`user`, `device`, `ai-draft`, `migrated`, `interface`) and `supersedes_id`.
- **C.** The bitemporal journal, written in the same transaction as the state change. One append-only row per change: aggregate type and id, patient id, valid time, recorded time, actor, on-behalf-of, device, purpose-of-use, reason, payload, previous version. It is the transactional outbox and the write-audit trail. It is never updated.
- **D.** Read models, rebuildable from the journal and pushed to clients over server-sent events (R08 §3.6).

**Event layers** (BUILD-PROMPT §5.3):
1. The clinical journal.
2. Domain events: CloudEvents 1.0 envelopes; schemas in Apicurio; backward-compatible evolution only, with a 12-month deprecation window; Debezium → Kafka keyed by patient; at-least-once delivery; idempotent consumers (ADR-009). The event catalogue (BUILD-PROMPT §8.5, canonical names after R11 §14) is a published product surface; BP's `ChargeGenerated` and `EncounterMoved` are aliases of `ChargeCreated` and `PatientTransferred`, never separate events.
3. Integration messages generated by the Hub from domain events (ADR-014).

**Identifiers and time:** UUIDv7 for every identifier; instants in UTC with the original offset; `tenant_id` on every row and `facility_id` where it applies; site-prefixed downtime number blocks. `TaskOrphaned` is a first-class alarm. Undeliverable messages land in owned queues that alarm after 5 minutes. Back-dating is privileged and audited; back-entry keeps valid time = paper time (BUILD-PROMPT §8.3).

## Consequences (including safety and licence impact)

**Safety.**
- Writing the journal in the same transaction as the state change means no committed change goes unpublished or unaudited (H6). This supports constitution rule 1 (everything derived is rebuildable from the journal) and rule 2 (facts are immutable and bitemporal).
- Bitemporal facts make signed-note immutability (SI-06) and clinical vs system time (SI-10) structural, and support back-entry after outages, which will be frequent in Kurdistan (SI-10).
- Because the journal is never updated, erasure duties are met by crypto-shredding under per-tenant keys (ADR-008), never by deletion. The 25-year retention floor and legal holds still apply (BUILD-PROMPT §2.3).

**Engineering.** A platform library must hide the journal mechanics, or the bitemporal model slows teams (R08 §13 #5). Full event sourcing stays an option for the medication aggregates only, behind the revert triggers below.

**Licence.** Debezium, Kafka and Apicurio are on the allowlist (BUILD-PROMPT §4.1, Apache-2.0). No new dependency.

## Fitness test that guards it

**Guard (BUILD-PROMPT §4.2):** Spike S2; performance suite.

**Where and when.**
- **Spike S2** runs inside the ADR-001 harness in `spikes/adr-001/` (WP-0.6). It measures BCMA and order-sign latency for the full-event-sourcing variant and reports the tooling effort as measurable proxies for a human to convert.
- **Performance suite:** `tests/performance/` (BUILD-PROMPT §6.1), in the nightly tier: a scaled functional day (about 30 beds) on the dev cell, compared with the same host's last baseline (indicative), and the 300-bed day on the reference cell once that hardware exists [HUMAN: hardware] (BUILD-PROMPT §19.1).
- **Related constitution checks** (not this ADR's named guard): the read-model rebuild test from the journal (WP-0.3 exit evidence) and the schema linter that forbids `UPDATE` and `DELETE` on fact tables (BUILD-PROMPT §6.8 items 2 and 10).

**State on 2026-10-18:** not implemented. This ADR claims no result.

## Reopen if

Tooling >8 engineer-weeks; BCMA p95 >500 ms; upcasting >20% of medication capacity; any C1 miss.

(BP §7.6 calls these the revert triggers for full medication event sourcing; "medication capacity" is BP's "the medication squad's capacity".)

Any change to this ADR is stop-and-ask item 2 (BUILD-PROMPT §3.4).
