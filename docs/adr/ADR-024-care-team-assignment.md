# ADR-024: Care-team assignment: an ES-lite core domain that feeds nurse call
Status: accepted
Date: 2026-10-18   Source: K §7.2 (kept), §9.2; BP §7.2, §7.3, §9.2; R16 §1 #2, #4, §2.2, §3.4, §3.5, §16, §17 #3; RL #7; BUILD-PROMPT §2.3, §5.2, §5.3, §8.5, §9.19, §12.8, §19.1, §21 (WP-0.3, WP-1.1b), §4.2

## Context

**The question.** How "who is assigned to which bed or patient right now" is held, and how it reaches nurse-call and clinical communication platforms.

**The research** (R16).
- Staff assignment is the integration everyone needs: nurse call, Vocera/Engage, Voalte, TigerConnect and RTLS all need to know who is assigned to which bed or patient right now. R16 says to make care-team assignment a first-class HMS domain with HL7 v2 and FHIR outputs; the alternative is a hand-typed assignment board in every vendor system (R16 §1 #4, §17 #3).
- Its scope (R16 §3.4 #1, tagged MVP in R16 §16): a unit charge-nurse board, patient-level and bed-level assignments, breaks and handoffs ("covering for"), and rostering import. It emits `StaffAssignmentChanged` to HL7 v2 and FHIR outputs; R16 §3.4 #2 adds a filtered ADT feed per nurse-call vendor, with bed-level location normalisation and replay.
- The HMS is never in the primary alarm path: secondary alarm delivery to phones is regulated, and nurse call is a standalone, certified life-safety system, so the HMS feeds these systems (ADT, staff assignments, risk flags) and consumes their events for documentation and analytics, but does not route alarms (R16 §1 #2).
- The nurse call must work without the HMS. If the feed stops, consoles show stale names; the mitigations are bed-anchored operation, a heartbeat monitor on the interface with a visible alarm in the Integration Hub, and replay on recovery (R16 §3.5).

**The conflict, and BP's resolution.** R16 asks for the assignment domain to be "event-sourced" (R16 §1 #4, §17 #3). RL #7 made event sourcing "lite" the standard and limited full event sourcing to order and MAR aggregates, by ADR. BP's ADR-024 settles the point: care-team assignment uses ES-lite ("resolves R16's RL #7 flag", BP §7.2), with no reopen trigger. BP §9.2 carries R16 §17's rule that care-team assignment is a core domain and feeds nurse call, and BP's system context shows the HMS sending "ADT and staff assignment" to facility systems (BP §7.3).

**Sources.** K keeps BP's ADR-024 (K §7.2) and the same rule among the four that carry over from R16 §17 (K §9.2). BUILD-PROMPT §4.2 joins the two statements. Not marked [P].

**Gaps, recorded.** BUILD-PROMPT gives the care-team assignment domain no feature ID in Appendix A, no owning module in §5.2 and no work package in §21. It also fixes no external format for the feed: R16 §2.2 maps `StaffAssignmentChanged` to HL7 v2 ADT A08 (PV1-7/ROL segments) or a custom feed, and to FHIR `CareTeam`/`PractitionerRole`, while the event catalogue lists it with no HL7 v2 mapping and FHIR "Internal" (BUILD-PROMPT §8.5). Both points are listed for `docs/program/OPEN-QUESTIONS.md` (BUILD-PROMPT §1).

## Decision

**Care-team assignment** uses ES-lite and is a core domain that feeds nurse call.

**Detail:**
- **ES-lite,** as ADR-004 defines it (BUILD-PROMPT §5.3): current-state tables, with one bitemporal journal row written in the same transaction as each change. The journal is the transactional outbox, and `StaffAssignmentChanged` is published from it through the event backbone (ADR-009). No full event sourcing (RL #7).
- **A core domain:** the HMS owns assignments, rather than each vendor system holding a hand-typed copy (R16 §1 #4). R16's scope for it is the charge-nurse board, patient-level and bed-level assignments, breaks and handoffs ("covering for") and rostering import (R16 §3.4 #1).
- **The event:** `StaffAssignmentChanged` is a catalogued domain event that feeds nurse-call and communications platforms (BUILD-PROMPT §8.5, §12.8).
- **Feeding nurse call:** the HMS feeds ADT and staff assignment to nurse-call and ACM platforms and consumes their acknowledgements, but is never in the primary alarm path (BUILD-PROMPT §2.3, §12.8). Consuming ACM acknowledgements is P2 (§9.19). Every external message is generated by the Integration Hub from domain events (ADR-014). Never build alarm routing or forwarding, nurse call or RTLS engines (§2.3).

## Consequences (including safety and licence impact)

**Safety.**
- One source of assignments replaces a hand-typed board in every vendor system (R16 §1 #4), so nurse-call and communication platforms work from the assignments the hospital actually made (H9).
- The nurse call keeps working without the HMS (R16 §3.5). A stopped feed shows stale names, so the Hub channel that carries it needs the same owned dead-letter queue, 5-minute alarm and ordered replay as every other channel (ADR-014; SI-03; H9, H15).
- ES-lite keeps every assignment change in the bitemporal journal with its actor and times (ADR-004).

**Licence.** None specific to this ADR.

## Fitness test that guards it

**Guard (BUILD-PROMPT §4.2):** Event tests.

**Where and when.**
- BUILD-PROMPT does not define the event tests further, and §21 places the care-team assignment domain in no work package (see Context). The tests can be written only when a work package builds the domain.
- What they depend on: the journal-as-outbox and per-patient event delivery with idempotent consumers (WP-0.3 exit evidence), and the merge tier's AsyncAPI contract tests for published events (BUILD-PROMPT §19.1), for which the local CI runner names WP-0.3. The outbound nurse-call feeds go through the Hub, from WP-1.1b (ADR-014).

**State on 2026-10-18:** not implemented, and not yet placed in a work package. This ADR claims no result.
