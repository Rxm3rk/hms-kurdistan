# Assumptions ([L] register)

Every [L] assumption from K Appendix B (L-1…L-37), with K's default and the configuration key that will hold it (BUILD-PROMPT §1, §3.1, §11, §23). None of these comes from the research pack; each is to be verified by the route and owner K gives, by the date shown (M0 = January 2027).

**Rules.**
- [L] assumptions are data. Every Kurdistan-specific fact lives in the Kurdistan pack as configuration with K's default; none is hard-coded (§1). Code that depends on one names it in a comment (for example `// [L] L-20`) and reads its value from the pack (§23).
- Configuration keys are proposed names [P] of the form `kri.<area>.<name>`. The pack is built as signed configuration in WP-1.1 (`PLT-CFG-02`) on the configuration chain from WP-0.3 (`PLT-CFG-01`). A key may change name when the pack is specified; this file is updated in the same slice.
- Values that implement a safety invariant or a fallback control set are vendor-locked: a tenant may tighten them and can never loosen them (§2.1). They are not pack values, and the table says so.
- "n/a" in the key column means no product behaviour reads the assumption (a market, staffing or business-plan assumption) or the assumption shapes scope rather than a value.
- **Status** is `not-built` for every row until the pack item exists; then `built` (key present with K's default) and `confirmed` only after the owner's verification is recorded with its date.
