**Summary: 0 critical, 3 major, 8 minor.**

The core is sound. `generate` refuses a spec with an unknown predicate (exit 1, nothing written). Rule 11 compares bytes exactly and cannot be fooled by a comment. The canonical SHA-256 is stable across CRLF, BOM, key order, Windows paths and the libyaml and pure-Python parsers. Escaping in the emitted Kotlin is correct. Every filled approval field is refused by both `check` and `generate`. The reviewed patient-context spec validates unchanged.

The weak spots: rule 12's "exactly one implementation" scan can be fooled through an intermediate interface or a type alias. Its "disabled test" scan misses Kotest's `!` and `f:` prefixes and `@EnabledIf`. Rule 13 passes silently in a shallow clone.

## Timing (fast-tier Python step)

`.tools/venv/Scripts/python.exe -I -B -m unittest discover -s tools/hmstools/statemachines -t tools -p 'test_*.py'` ran 88 tests, all OK. Wall time was 1 m 30.5 s (unittest's own figure 87.7 s) on the loaded host. A second run with per-test timing took 59.3 s. `-B` was added only to stay read-only; the `__pycache__` is already there, so this costs nothing measurable.

Slowest tests (second run): `Rule13.test_unchanged_spec_keeps_its_record` 8.0 s (it runs a full `check` twice), `Rule13.test_a_record_removed_and_added_again_is_checked_at_every_addition` 4.0 s, `Rule13.test_the_required_roles_count` 3.1 s, `Rule13.test_record_added_before_the_spec` 3.0 s, `Rule13.test_a_content_change_without_a_version_bump_fails` 2.9 s, `Rule13.test_a_later_record_...` 2.5 s, `Rule13.test_records_of_other_subjects_...` 2.1 s, `Rule13.test_record_not_committed` 2.1 s, `Cli.test_check_json_passes` 1.6 s, `CleanSet.test_one_machine_only` 1.1 s.

Per class: Rule13 33.0 s, Rule11 7.4 s, Rule12 6.5 s, Violations 4.9 s, Cli 2.6 s, CleanSet 2.3 s, Golden 2.0 s, everything else under 0.4 s.

Where the time goes:
- Git process spawns cost about 0.14 s each on this host (10 × `git --version` = 1.4 s). Each Rule13 test spawns about 10-14: `init`, 4 × `config`, 2-3 × `add`/`commit`, then `log` and `show` inside the check.
- Every `check` re-runs `check_schema` (0.08 s warm, 1.5 s cold per process) and regenerates the toys in memory.
- `implementation.scan` is a per-character Python loop. On the real repository it is 2.8 s of a 7 s profiled check, mostly spent scanning the large generated `*Machine.kt` files, and the adt project is scanned twice (encounter and bed).

### How to make it faster without weakening it
1. **Rule13: build the repository once.** In `setUpClass`, create a template repository (init, identity, `commit.gpgsign=false`, `core.autocrlf=false`, the toy spec, and record SO-2026-0901 committed). Copy it per test with `shutil.copytree`, or `git clone --local`, which is cheap. That removes init, 4 configs, add and commit from about 8 of the 13 tests. Alternatively, pass the identity and config through the environment (`GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL`, `GIT_CONFIG_COUNT/KEY_n/VALUE_n`) to drop the 4 `git config` spawns everywhere.
2. **Rule13: call the rule, not the whole check.** In tests that only read rule-13 messages, call `approval.load_records` + `approval.rule_13(...)` directly with `canonical_text(load_spec(spec))`. Keep two end-to-end tests through `run_check` (pass and fail) so the wiring stays tested. In `test_unchanged_spec_keeps_its_record`, run the check once and assert on both `errors` and `counts`.
3. **Cache the schema per (path, mtime).** `check._schema` should cache like `_hazard_ids_cached` does. The validator itself is already cached in `safety.check._VALIDATORS`. This saves 0.08 s × about 120 checks.
4. **Rule 12 scan:** skip files whose first line is the generated marker (rule 11 already pins their exact content, and they never implement anything). Scan each project once per run, not once per machine. That speeds up the real `check` (7.8 s now) as well as the tests.
5. **Golden/Rule11/Rule12 setUp:** generate the toy files once per class and copy them per test, instead of running `generate` in every `setUp`.

None of these removes an assertion or a case; together they should bring the suite to roughly 20-25 s on this host.

## Checked and found sound

- **Unknown predicate (wp05 scope item 3):** rule 4 is part of `spec_rules`, so `run_generate` writes nothing for a failing spec and returns a failed `CheckResult`, which means exit 1 (`common.CheckResult.emit`). Covered by `test_rule_4` and `Rule11.test_a_failing_spec_is_not_generated`. Undeclared effects and unused predicates and effects fail too.
- **Rule 11 cannot be fooled by text tricks:** `_difference` compares the exact decoded bytes against freshly generated text. A comment, a CRLF conversion, a hand edit, an old generator version, a missing file, or an orphan file carrying the header (inside the targets' projects) all fail. A comment or layout change in the *spec* correctly keeps the files current.
- **Canonical SHA-256 is platform-stable:** LF vs CRLF vs BOM+CRLF give identical hashes, including with block and folded scalars (`probe.py` G). All 8 real specs and patient-context hash identically under `CSafeLoader`, a pure-Python `SafeLoader` variant with the same resolvers, and CRLF input (`cvspy.py`). JSON is sorted, compact and UTF-8 (`ensure_ascii=False`). The header path is `relative_to(root).as_posix()`. The reduction is the sign-off gate's own (`so._plain`), tested equal to `content_version(doc, "approved")`. A CRLF spec against LF generated files passes `check`.
- **Kotlin escaping:** string literals escape `\`, `"`, `$` (so `${x}` becomes `\${x}`), `\n`, `\r`, `\t` and other control characters. KDoc collapses whitespace and breaks both `*/` and `/*`, because Kotlin comments nest. Long strings split only between pieces of raw text, so an escape is never cut. Widths count UTF-16 units. All 16 committed generated files have no line over 140 columns and no comment opener inside a KDoc. Hard keywords are refused as predicate names, and constant-name clashes are refused.
- **Approval:** each of `status: approved`, `status: returned`, `approved_by: [X]`, `record: SO-1`, `record: ""` fails rule 9 alone, and `generate` refuses the spec too. The schema's `additionalProperties: false` (top level, approval block, transitions) leaves no other place for a human field. `approval_fields_filled` counts 0 on the real specs.
- **Reading rules:** `on/off/yes/no/y/n` stay strings; `True/YES/On/N...` fail; dates stay strings; duplicate keys, merge keys and non-string keys fail. A trailing newline smuggled into a command (`"SwitchOff\n"`) is rejected by the schema.
- **Patient-context (`fcadc88`):** the fixture is byte-identical to `git show fcadc88:docs/specs/state-machines/patient-context.yaml` (diff empty; blob ids pinned in `test_rules.ForeignSpec`). `validate.py` reports 0 errors and 24 transitions. Rules 1-10 and 13 pass, its five `OpenSign` alternatives pass rule 5, and it is not generated.
- **Rules 2-8, 10** match spec §2.1 as written, including `"*"` expansion excluding `to`, rule 7 on `"*"` transitions that cover terminal states, rule 6 for recurrent machines, and the rule 5 subset test including the empty guard. Rule 9's approver table matches §8.4 for all eight machines (`test_rule_9_every_section_8_4_machine_has_its_list`).
- **Rule 13 in a full clone:** every adding commit is checked, including re-additions. A record committed before the spec fails, an uncommitted record fails, an unreadable record fails, and a repository without history fails. Changing the required roles counts as a content change; comments and human fields do not.
- **Live run:** `sh tools/hms statemachines check` (7.8 s) passes rules 1-11 and 13 for all 8 machines (228 transitions, 231 predicates, 16 generated files current, 0 approval fields filled). Rule 12 fails for every machine because no `<P>Guards`/`<P>GuardsTest` exists yet. That is work in progress, but it means the fast tier is red until those land.
- **CI wiring diff:** `state-machines-check` runs `sh tools/hms statemachines check --json` with `check_json=True` and a 300 s timeout, after `safety-check`. `BACKEND_JUNIT` adds `tests/**/build/test-results/**/*.xml`, and the new test shows stale results are cleared. The §7 nightly steps (`property-1e6`, `si-domain-layer`, `scenario-suites`), the `si-status` subcommand and the `backend-fast` counts (`pbt_sequences`, `si_spec_layer_holds`, `si_domain_not_built`) are not wired yet. That is planned as slices S3/S4 in `docs/program/STATUS.md` lines 21-22, and `si-status` is pinned as a usage error by `test_usage_errors_exit_2`, so it is not a finding. Make sure S4 replaces the `NIGHTLY_NOT_BUILT` rows that still name WP-0.5.
- **Tests are meaningful:** one fixture per rule with exact message fragments, golden files checked with ktlint/detekt, byte stability, layout limits, CLI exit codes 0/1/2, sandboxed git with isolated config, and nothing written to the repository. Gaps are the bypasses in py-01/02/03/04/08 (no test covers them) and CRLF-spec stability (verified sound here, worth a test).
