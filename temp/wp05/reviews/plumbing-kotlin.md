## Checked and found sound

- **`fire` semantics** (`MachineSpec.kt:74-92`). `candidate.guard.filterNot(holds)` evaluates every predicate of every candidate, once per candidate, with no short-circuit. Exactly one holding candidate gives `Fired`; two or more give `Ambiguous`, which keeps the state and produces no effect (the `Outcome.Ambiguous` `state`/`effects` getters). None gives `Refused`, listing every candidate in spec order with its failed predicates in guard order, and `Refused.init` rejects an empty list. No candidate gives `NotApplicable`. A creation command or a state outside the machine also gives `NotApplicable`, so nothing changes. `MachineSpecTest` covers each of these, including the evaluation order (`:144-157`) and a hand-built ambiguous pair (`:159-165`). The constructor checks match contracts §2: initial, terminal, from/to, index order, duplicates, unknown commands and creators.
- **The harness checks against its own evaluation.** The flaky-predicate self-tests (`SequenceHarnessTest.kt:237-256`) show that P2 catches an engine that fired, or refused, against a re-evaluation of the predicates. P3 catches `Ambiguous` and also a second holding candidate. P5 is checked against `holding`, not against the transition's guard, and fails closed when a machine with terminal exits has no `PRIVILEGED_AND_AUDITED` predicate. P7 lists every transition that never fired, with the master seed, and is asserted whenever `budget >= 1000`, so at both the fast budget (1,000) and the nightly one (10⁶).
- **Sequence shape.** Each sequence starts in `initial` and has 1 to `maxSteps` steps, drawn from `RandomSource.seeded(seed)`. The bias of 0.85 chooses among the commands that have a transition from the current state, and otherwise among all commands, creation commands included. There is no Kotest per-iteration machinery in the loop. Each of these is tested (`:140-235`). The same master seed gives an identical `RunStats` and an identical failure message (`:313-330`, `:385-389`).
- **Budget source.** `SequenceConfig.budget` defaults to `PropertyTestBudget.sequences()`, read from the system property `hms.pbt.sequences`. `hms.test-conventions` sets that property from `-Phms.pbt.sequences` (default 1000) on every Test task, and the CI fast step passes `-Phms.pbt.sequences=1000 --no-build-cache`. The generated tests and `ToyDoorSequencePropertyTest` hard-code no count. The fixed 300/1,000 budgets in `SequenceHarnessTest` are self-tests of the harness, not machine properties, and are labelled as such (`:27-28`).
- **Counts file content.** The keys and their order match spec §3.3 and contracts §6. Names are sanitised to `[A-Za-z0-9._-]` and JSON strings are escaped. Nothing is written when `hms.pbt.countsDir` is absent. The last run's `toy-door.json` shows 1,000 sequences, 16,833 steps and 10 of 10 transitions covered.
- **Scenario framework fails closed.** An unbound suite gives NOT-BUILT for every catalogued scenario. A catalogued scenario that the binding does not implement stays NOT-BUILT. A scenario with no `then` step fails, as do one belonging to another suite, a duplicate id, an exception from `ports()` and an unbound port. `ScenarioNotBuiltException` gives NOT-BUILT. A suite reads FAIL before NOT-BUILT before PASS. The run is PASS only when every suite passed, and an empty catalogue is FAIL. The exit code is 1 otherwise, so `JavaExec` fails the task, and the matrix is written before the exit. `scenarioSuites` sets `upToDateWhen { false }` and is not part of `fastTier`. NOT-BUILT is never reported as PASS and never skipped. All ten suites are catalogued as NOT-BUILT under KA-064. CPOE is labelled mock-KB, per §18.5 #1, and so is ISMP, which is the stricter choice. The world uses a fixed `SimulatedClock` in `Asia/Baghdad` and issues only `SYN-` patients.
- **ktlint filter fix** (`hms.quality-conventions.gradle.kts`). Adding `File.separator` to the build-directory prefix is correct: before the fix, `<project>/build.gradle.kts` started with `<project>/build` and was excluded. Both sides are `File.absolutePath`, so the separators agree on Windows. There is no host evidence of a script-lint run after the fix: the subproject `build/reports/ktlint` directories predate the edit (07:43, against 07:49) and have no `ktlintKotlinScriptCheck` folder. The lead's WSL run should confirm it.
- **Catalogue entry.** `kotest-framework-engine` uses `version.ref = "kotest"` (6.2.6, an exact pin, already recorded in ADR-002). It is Apache-2.0 and was already resolved transitively in the Gradle cache. `SOURCE_SETS` now includes `testFixtures`, so detekt and ktlint cover it.
- **Settings and module skeletons.** The project paths and directories match contracts §1 and spec §3.1, and `rcm` is under `satellites/`. Each module applies the three conventions and `java-test-fixtures` and depends `api` on `:platform:state-machine`. `platform/testing` depends `api` on the engine and on Kotest, without a project cycle. The modules currently have no `src/test/.../ArchitectureTest.kt`, and `verifyArchitectureTest` will fail `fastTier` until the phase-2 agents add them, which is fail-closed.
- **Domain-purity rule (d)** covers `now()` without a `Clock` on every `java.time` type, the system `Clock`/`InstantSource` factories, `currentTimeMillis`, `nanoTime`, `Date()`, `Calendar` and the Kotlin and kotlinx clocks, for every `hms..domain..` class in main. That includes the generated machines. kt-08 lists what it leaves out.
