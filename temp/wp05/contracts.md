## 2. Engine: `backend/platform/state-machine`, package `hms.kernel.statemachine`

```kotlin
data class Transition<S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>>(
    val index: Int,            // position in the YAML transitions list, 0-based
    val from: Set<S>,          // "*" already expanded: every state except `to`
    val on: C,
    val guard: List<P>,
    val to: S,
    val effects: List<E>,
    val proposed: Boolean,     // its edge is listed in the spec's `proposed`
)

class MachineSpec<S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>>(
    val machine: String,
    val version: Int,
    val states: List<S>,
    val initial: S,
    val terminal: Set<S>,
    val createdBy: List<C>,
    val commands: List<C>,     // every command of the machine, creation commands included
    val transitions: List<Transition<S, C, P, E>>,
) {
    fun candidates(state: S, command: C): List<Transition<S, C, P, E>>
    fun fire(state: S, command: C, holds: (P) -> Boolean): Outcome<S, C, P, E>
}

sealed interface Outcome<S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>> {
    val from: S
    val command: C
    val state: S                // the state after the step (== from unless Fired)
    data class Fired<...>(override val from: S, override val command: C, val transition: Transition<S, C, P, E>) : Outcome<...>
        // state = transition.to; effects = transition.effects
    data class Refused<...>(override val from: S, override val command: C, val failed: List<Pair<Transition<S, C, P, E>, List<P>>>) : Outcome<...>
    data class NotApplicable<...>(override val from: S, override val command: C) : Outcome<...>
    data class Ambiguous<...>(override val from: S, override val command: C, val matching: List<Transition<S, C, P, E>>) : Outcome<...>
}
```
`fire` evaluates every predicate of every candidate exactly once per candidate (no short-circuit). Exactly one candidate
whose guard fully holds → `Fired`; more than one → `Ambiguous` (no state change); candidates but none holds → `Refused`
(each candidate with its failed predicates, in guard order); no candidate → `NotApplicable`. The constructor validates
the spec (initial in states, terminal ⊆ states, every from/to in states, indexes 0..n-1 in order) and throws
`IllegalArgumentException` otherwise. Pure Kotlin, no dependencies beyond the Kotlin stdlib.

## 3. Generated main file: `<P>Machine.kt` (example for a two-state toy machine `toy-light`, owner `adt`)

```kotlin
// GENERATED by tools/hms statemachines generate (generator 1) from docs/specs/state-machines/toy-light.yaml
// sha256 of the canonical spec: <64 hex>. Do not edit: change the spec and run `sh tools/hms statemachines generate`.
package hms.adt.domain.toylight

import hms.kernel.statemachine.MachineSpec
import hms.kernel.statemachine.Outcome
import hms.kernel.statemachine.Transition

/** States of the toy-light machine (docs/specs/state-machines/toy-light.yaml). */
enum class ToyLightState(
    val id: String,
) {
    OFF("off"),
    ON("on"),
}

/** Commands of the toy-light machine. */
enum class ToyLightCommand {
    Install,
    SwitchOn,
    SwitchOff,
}

/** Guard predicates of the toy-light machine; each is implemented once in [ToyLightPredicates]. */
enum class ToyLightPredicate(
    val id: String,
    val description: String,
) {
    POWER_AVAILABLE("powerAvailable", "mains or generator power is present"),
}

/** Effects of the toy-light machine. */
enum class ToyLightEffect(
    val id: String,
    val description: String,
)

/** The guard predicates of the toy-light machine, implemented once by the domain (ToyLightGuards). */
interface ToyLightPredicates {
    /** mains or generator power is present */
    fun powerAvailable(facts: ToyLightFacts): Boolean
}

/** The executable toy-light machine, generated from its specification. */
object ToyLightMachine {
    const val MACHINE: String = "toy-light"
    const val VERSION: Int = 1
    const val SOURCE_SHA256: String = "<64 hex>"

    val spec: MachineSpec<ToyLightState, ToyLightCommand, ToyLightPredicate, ToyLightEffect> =
        MachineSpec(
            machine = MACHINE,
            version = VERSION,
            states = ToyLightState.entries,
            initial = ToyLightState.OFF,
            terminal = setOf(),
            createdBy = listOf(ToyLightCommand.Install),
            commands = ToyLightCommand.entries,
            transitions =
                listOf(
                    Transition(
                        index = 0,
                        from = setOf(ToyLightState.OFF),
                        on = ToyLightCommand.SwitchOn,
                        guard = listOf(ToyLightPredicate.POWER_AVAILABLE),
                        to = ToyLightState.ON,
                        effects = listOf(),
                        proposed = false,
                    ),
                    ...
                ),
        )

    /** Evaluates [predicate] with the domain's single implementation [predicates]. */
    fun holds(
        predicate: ToyLightPredicate,
        predicates: ToyLightPredicates,
        facts: ToyLightFacts,
    ): Boolean =
        when (predicate) {
            ToyLightPredicate.POWER_AVAILABLE -> predicates.powerAvailable(facts)
        }

    /** Applies [command] in [state] with [facts]; never changes state unless exactly one guard holds. */
    fun fire(
        state: ToyLightState,
        command: ToyLightCommand,
        predicates: ToyLightPredicates,
        facts: ToyLightFacts,
    ): Outcome<ToyLightState, ToyLightCommand, ToyLightPredicate, ToyLightEffect> = spec.fire(state, command) { holds(it, predicates, facts) }
}
```
The exact layout (line breaks) is whatever ktlint_official accepts unchanged; the generator owns it. An empty enum (no effects)
is `enum class XEffect(val id: String, val description: String)` with no entries, which Kotlin accepts. Descriptions are
emitted as Kotlin string literals with `"`, `\` and `$` escaped; KDoc text has `*/` broken up.

## 4. Hand-written, per machine (same package)
- `src/main/kotlin/.../<P>Facts.kt`: `data class <P>Facts(...)`: the facts the predicates read (pure values, `java.time`).
- `src/main/kotlin/.../<P>Guards.kt`: `object <P>Guards : <P>Predicates { override fun ...}`: the ONLY implementation.
- `src/test/kotlin/.../<P>GuardsTest.kt`: Kotest unit tests; for every predicate at least one case where it holds and one where it does not, each test name containing the predicate's camelCase name.
- `src/testFixtures/kotlin/.../<P>Arbs.kt` (the module applies `java-test-fixtures`; `testFixturesImplementation(libs.kotest.property)` is already there): `object <P>Arbs { val facts: Arb<<P>Facts> }`, biased so that every transition's guard holds often enough for property P7 (every transition fires at least once in 1,000 sequences).
- `src/propertyTest/kotlin/.../<P>PropertyTest.kt`: machine-level properties (spec §3.3) using `runSequences` (below).

## 6. Harness: `backend/platform/testing`, package `hms.kernel.testing.statemachine`
(`platform/testing` gains `api(project(":platform:state-machine"))` and `api(libs.kotest.property)` and `api(libs.kotest.framework...)` as needed.)

```kotlin
data class SequenceConfig(
    val budget: Int = PropertyTestBudget.sequences(),
    val maxSteps: Int = 32,
    val applicableBias: Double = 0.85,     // share of steps that pick a command with a transition from the current state
    val coverageFromBudget: Int = 1000,    // P7 is asserted when budget >= this
)

data class Step<S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>, F>(
    val seed: Long,        // the sequence's seed (reproduces the whole sequence)
    val index: Int,        // step index within the sequence, 0-based
    val from: S,
    val command: C,
    val facts: F,
    val outcome: Outcome<S, C, P, E>,
    val holding: Set<P>,   // every predicate of the machine that holds for these facts (evaluated by the harness)
)

class StepCheck<S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>, F>(
    val name: String,
    val check: (Step<S, C, P, E, F>) -> Unit,   // throws AssertionError (use Kotest matchers) on a violation
)

data class RunStats(
    val name: String, val machine: String, val budget: Int, val sequences: Int, val steps: Long,
    val fired: Long, val refused: Long, val notApplicable: Long, val ambiguous: Long,
    val transitionsCovered: Int, val transitionsTotal: Int, val firedPerTransition: List<Long>,
)

/** Runs config.budget seeded sequences, applies P1-P6 and every check after every step, returns the stats and writes
 *  the counts file. P7 is NOT asserted here (callers decide); a failure message names the seed and the step. */
fun <S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>, F> runSequences(
    name: String,
    spec: MachineSpec<S, C, P, E>,
    holds: (P, F) -> Boolean,
    facts: Arb<F>,
    config: SequenceConfig = SequenceConfig(),
    checks: List<StepCheck<S, C, P, E, F>> = emptyList(),
): RunStats

/** A Kotest test factory with one test: "<name>: P1-P7 hold over <budget> random command sequences". */
fun <S : Enum<S>, C : Enum<C>, P : Enum<P>, E : Enum<E>, F> machineSequenceProperties(
    name: String,
    spec: MachineSpec<S, C, P, E>,
    holds: (P, F) -> Boolean,
    facts: Arb<F>,
    config: SequenceConfig = SequenceConfig(),
): TestFactory
```
Counts file: `<System.getProperty("hms.pbt.countsDir")>/<name>.json` (name with characters outside `[A-Za-z0-9._-]` replaced
by `_`), JSON with keys `name, machine, budget, sequences, steps, fired, refused, not_applicable, ambiguous,
transitions_covered, transitions_total`. When the property is absent (an IDE run), nothing is written. Gradle's
`hms.test-conventions` sets `hms.pbt.countsDir` to `<project build dir>/pbt-counts` for every Test task.
The sequence loop does NOT use Kotest's per-iteration machinery for steps: it draws `config.budget` seeds and, per seed,
builds a `RandomSource.seeded(seed)` and samples commands and facts from it, so 10⁶ sequences stay fast and a seed
reproduces a failure.
