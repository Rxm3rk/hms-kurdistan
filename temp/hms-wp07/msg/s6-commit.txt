feat(web): WP-0.7 S6 web frame, clinical layout and demo route

Slice S6 of WP-0.7 builds the web client of
docs/specs/modules/design-system.md §2.2, §2.9, §4 and §5 in
frontend/apps/web.

What S6 adds:
- The frame (src/frame): LocaleProvider from ?locale=, the modal stack,
  DensityProvider from ?density=, the React Aria router, a skip link,
  the navigation, the command palette, the language picker, the density
  control, a patient-context status region, the switch confirmation,
  the demo watermark, the document title from the catalogue and a
  focus-time check of the session user.
- Routing (src/routing): code-based TanStack Router routes built by
  createAppRouteTree; `clinical: boolean` is required on every route's
  staticData by type; the pathless `_clinical` layout renders
  PatientBanner and the close control, the chooser when no patient is
  open, and nothing patient-specific while the address and the context
  name different patients; a string-only, Zod-validated search format.
- The patient context (src/patient): one store per window that applies
  ui-core's transition and adds no rule; the address is a request,
  never a selection; an unknown patient is never opened (the address is
  put back), while a failing directory opens the patient with the
  banner's error state and signing blocked; only the latest request
  counts and an overtaken or cancelled request sends nothing; the
  TanStack Query cache is keyed by patient, has no network mode, retry
  or refetch, and is pruned after every transition; random v4 UUID
  idempotency keys from getRandomValues; the §2.2 switch confirmation
  (an alertdialog whose Confirm asks the machine through
  enabledTransitions) and a GridList patient chooser.
- The demo (src/demo): /demo/banner under `_clinical`, 25 synthetic
  Zod-validated fixtures covering every §5 case, a synthetic user, the
  simulated authenticator and submitter, and an abstract synthetic
  photo. The app imports src/demo/selected.ts (null); a Vite resolveId
  plugin swaps in src/demo/index.ts only for `vite build` with
  VITE_HMS_DEMO=1 and, by default, for the development server.
- Built pages carry a Content-Security-Policy (default-src 'none', own
  origin only, React Aria's two style elements by hash, Zod jitless);
  servers listen on 127.0.0.1 only. Logical CSS only.
- S1's smoke test gets a 20 s test timeout (it timed out at 5 s beside
  the whole-app tests).
- OQ-163 (open; S6's engineering choices, including the stricter
  reading that hides the banner while the address and the context
  disagree, for the CSO) and KA-044 (open; the last number of WP-0.7's
  KA range: no patient, user or clinical route in a production build
  until WP-0.4, user change noticed on window focus only, missing
  catalogue keys, react-intl's MISSING_DATA for ckb, the HAL capture
  binding not wired).
